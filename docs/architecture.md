# 架构与数据口径

## 数据流

`行情适配器 → 校验与技术计算 → SQLite 快照/报告 → HTTP 接口 → 浏览器`

UI 不调用行情供应商、DeepSeek 或飞书。AI 只负责将验证后的结构化事实转成中文，不决定是否触发事件。笔记仅存 SQLite，不进入模型上下文。

外部数据源在独立子进程内获取，行情总超时 65 秒，基本面总超时 25 秒。每个市场最多并发处理 3 只股票。AI 请求超时 40 秒，禁用 SDK 内自动重试。先保存快照与规则报告，再补基本面和 AI，防止慢服务阻挡整页使用。

## 报告与日期

- 港股使用 `Asia/Hong_Kong` / XHKG；A 股使用 `Asia/Shanghai` / XSHG。两地市场分别调度和归档。
- `market.py` 使用 XHKG 交易日历，区分周末、假日、午休、半日市与收盘后等待期。港股收盘等待 15 分钟；A 股等待 45 分钟，覆盖盘后固定价格交易及数据落地，且行情日期须符合应完成交易日。
- 每份记录同时保存 `report_date`、`data_date` 和 `created_at`。盘前的报告日期是今天，数据日期是上一交易日；收盘报告日期等于实际行情日期。
- 当数据源滞后时，只归档它实际提供的历史日期，状态标成等待更新；不会对“今日收盘”做成功标记。
- `snapshots(symbol, trade_date)` 每个交易日保留最近一次快照，盘中快照会被收盘版替换；事件独立保存，不会随快照替换而丢失。网站并未保存逐分钟行情。
- `reports.id` 包含股票、报告日期、类型；盘中记录还包含事件类型。同一种事件每天只存一次。AI 失败可在同一条记录补齐，不另造重复记录，也不覆盖已成功的 AI 解读。
- 打开某只股票只将本次返回的记录标为已读；浏览历史日期不会清除其他日期的新事件。
- 单次接口最多返回 400 条记录。更长历史可通过日期筛选访问；数据库不会因此删除旧记录。

## 技术数据

- 行情来源自动回退，并在快照中记录实际来源。Yahoo 使用调整后日线；不同供应商的复权方式可能不同，跨来源对比仍需谨慎。
- Yahoo 的结束日期为排他边界，采集窗口包含当天。日线盘中值可能延迟，并不是逐笔实时行情；网页明确标为盘中参考。
- 成交量倍数 = 当日成交量 / 前 20 个交易日平均成交量，不包含当日，不应称为常见行情终端的实时“量比”。盘中事件不使用全天成交量倍数判断放量。
- 至少 20 根有效日线才生成分析；不足 120 日的长周期均线显示“数据不足”。历史区间使用真实起止日期和交易日数。
- KDJ 的金叉、死叉比较前后两日 K/D，单纯 K 高于 D 不称为刚刚上穿。
- 支撑、阻力、技术区间事件使用上一交易日的固定参考位。突破、离开区间的判断需要前后数据，不让移动后的区间制造变化。
- 参考区间是技术计算，并非合理估值、目标价或买点。价格跌破支撑后不再把区间机械移到现价附近。
- 财务和新闻仍依赖旧版 AKShare 接口。缺失字段直接显示未获取；金额来源币种尚未可靠提取，因此不擅自标成人民币/港币。现金跑道等尚未充分验证的指标不在新界面中展示。

## MACD / KDJ 图表

`backend/indicators.py` 统一计算最新指标、历史序列与简短规则解读，`analyzer.py` 和快照生成都复用它。序列先用全部可用日线计算，再保留最近 120 个交易日；前端只切换显示范围，不重新计算 EMA 或 KDJ。解读比较最后两个交易日，并非所选区间的整体回测。

| 图表 | 观察问题 | 图形与基准 | 数据与颜色 |
| --- | --- | --- | --- |
| MACD (12,26,9) | 快慢线关系、动能增减 | DIF / DEA 折线、从零轴起算的正负柱 | 同一快照日线；金棕实线、青蓝虚线；延续用户指定红涨绿跌，正柱实心、负柱空心辅助区分 |
| KDJ (9,3,3) | 短线高低位、当日是否出现交叉 | K / D / J 三线，20 / 50 / 80 参考线 | 金棕实线、青蓝虚线、灰紫点线；J 值超出 0–100 时自动扩展纵轴 |

- MACD：DIF = EMA12 − EMA26；DEA = DIF 的 EMA9；柱值 = 2 × (DIF − DEA)。EMA 从首个价格递推，前 34 日属于初始化阶段，不绘制，也不生成 MACD 解读。
- KDJ：RSV 取最近 9 日高低价区间位置，K、D 按 1/3 权重递推，初始值 50；J = 3K − 2D。前 8 日不绘制，九日高低价相同时使用中性 RSV = 50，避免除零。
- 正负柱的放大与缩短使用绝对值比较；金叉/死叉必须发生前后两日穿越。双线位于零轴上方不代表柱值一定为正。
- 每张图显示参数、最新值、实际日期范围与规则解读；30 / 60 / 120 日控制同时作用于主图和两组指标。窄屏指标图可横向滚动，保持坐标标签可读。早期有效点不足两点时不连线。
- 旧版快照只保存收盘价和成交量，无法可靠回算 KDJ；这类存档明确显示缺少序列，下一次成功采集会将新快照补齐，不把新行情冒充旧存档。
- 数值用独立递推公式、平价/交叉/负柱收窄案例验证；同时检查日线与指标日期一致、显示范围不改变末值、J 不裁剪、缺数据不造曲线。

## 维护约束

1. 业务状态只写 `store.py`，不在页面或路由中直接写数据库。
2. 新的数据源只加适配器，不改页面；在 `prices.py` 校验后才接受，异常日线触发回退。
3. 新事件在 `reports.py` 实现确定性规则，再复用时间线展示。
4. 页面样式改 `frontend`，不把展示 HTML 放进业务后端。
5. 第一版使用一个进程和 SQLite；部署增长确有需要时才引入队列或外部数据库。
6. 不恢复旧飞书任务。未来通知渠道如果需要，应订阅已存事件，不能与采集流水线耦合。

## 双市场边界

同一应用工厂实例化两份共用实现的 `ResearchService`，分别加载两份配置和独立 SQLite 文件。每个接口通过 `market=HK|A` 明确选择市场，省略时仍为 HK 以兼容旧链接。服务端再次检查股票属于该市场关注列表，不能仅凭股票名称混用 A/H 股。

前端路由为 `#HK/overview`、`#A/overview`、`#A/stock/002594` 等；旧 `#stock/00700` 仍有效。切换市场清除旧页面和日期筛选，丢弃过期异步请求，草稿按市场与代码保留。市场选择只改变视图及当前市场的更新操作，另一市场继续独立调度。

沪深股票分别显示 `.SH` / `.SZ`，行情使用 CNY；港股显示 `.HK`，行情使用 HKD。财报币种按财报来源单独标明。A 股迁移、远端停用与目录保留说明见 [迁移记录](a-share-migration.md)。
